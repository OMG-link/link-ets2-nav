# 探头标定

未经标定但已确认挂点部件有效的探头，在直线距离进入 500 米时播报一次“正靠近未校准的探头，无法获取其监测方向，请减速慢行。”；提醒不依赖导航路线，可能包含对向或邻路探头，不代表该探头会对当前车辆测速。标定记录描述挂点局部坐标系中的监测位置和有效行驶方向；不记录道路上的固定世界坐标或预计算触发点。

## 配置位置

在宿主输出目录的 `Settings/LinkEts2Nav.CameraCalibrations.json` 中配置。插件每五秒重新读取，文件不存在时使用空配置。格式错误会使整份配置失效，并在诊断页面显示原因。

空配置如下：

```json
{
  "schemaVersion": 1,
  "entries": []
}
```

每条记录需要以下字段：

| 字段 | 内容 |
|---|---|
| `descriptor` | 模型的完整虚拟 PMD 路径 |
| `hookup` | 实际测速挂点单位，例如 `speedcam.20` |
| `locator` | 探测工具输出的 `LocatorName`，不是地图条目 UID |
| `variant` | 当前模型变体，必须和探测结果一致 |
| `metadataFingerprint` | 探测工具输出的 64 位 SHA256 元数据指纹 |
| `travelAxis` | 已验证的有效行驶方向，取 `+X`、`-X`、`+Z` 或 `-Z` |
| `monitoredOffset` | 实际监测位置相对挂点的局部偏移，包含数值字段 `x`、`y`、`z`，单位米 |
| `evidence` | 标定依据，包括游戏版本、验证场景和结果 |

`travelAxis` 指最终测速方向，不是镜头朝向；对于带反向参数的挂点也必须填写实际验证过的方向，配置应用时不会再次反转。偏移在挂点局部坐标中定义，插件根据当前地图实例的位置、旋转和缩放实时转换，不随地图更新保留旧世界坐标。

插件还会检查挂点所属模型部件在所选变体中是否有效。关闭测速挂点的变体不能通过普通校准记录重新启用。

## 验证步骤

1. 启用插件，在诊断页取得车辆世界坐标和附近目标，确认目标确实来自真实测速挂点。
2. 使用资源探测工具检查该区域，记录模型路径、挂点、变体及指纹。仅有模型旋转或 `reverse_direction` 参数不足以证明绝对测速方向。
3. 诊断页在内存中保留本会话最近 64 条罚款观测，并单独保留最近测速罚款；`speeding_camera` 表示测速探头罚单。事件不包含探头 UID，显示的位置可能有轮询延迟，不能直接当成精确测速位置。结合该信息，在游戏中确认同一路段两个行驶方向的实际测速行为，以及触发位置相对挂点的偏移。区分路旁模型、挂点和监测位置，不直接把配置中的 `measurement_distance` 当成偏移量。
4. 为已验证的模型、挂点和变体建立记录，填写验证依据。先验证单个目标，再覆盖反向通行、弯道、相邻道路和跨层道路。
5. 检查预警在约 500 米和 200 米处各触发一次，经过后不重复；改变路线、读档和暂停期间没有错误提示。

测试与资源解析成功只证明实现和格式处理正确，不能代替上述游戏内验证。项目不附带未经验证的通用方向配置。

## 更新行为

指纹包含挂点元数据、测量参数、模型部件和 PMD 内容。当相关资源变化或变体不匹配时，原记录不再启用预警，目标回到未验证状态。仅道路或摆放位置变化时，局部标定仍由新地图实例重新计算，避免维护全地图触发点。

如果地图、模型或挂点被活动模组覆盖，第一阶段扫描会暂停并提示模组名称。应先确认资源来源，再决定是否支持该覆盖；不要沿用官方模型的校准数据猜测模组行为。

## 罚款事件的读取限制

原生遥测的 `fined` 是事件翻转位，每次罚款改变一次，两个方向都表示事件；不是“true 表示正在罚款”。插件忽略连接时的初始残留值，在观测变化后等待后续稳定采样，再记录首次发现时的位置和时间。

日志逐笔排空有界队列，因此后来的疲劳罚款不会覆盖尚未输出的测速记录。读档、传送或重连会清理当前显示历史，但已捕获的队列仍可输出。队列满时会记录溢出数量。仅发现类型或金额变化、没有观察到翻转时，会标注为不确定信号。

共享内存不是完整事件日志，且标志与属性不是原子写入。确认采样降低读取中间状态的风险，不能保证恢复采样间隔内已被覆盖的多笔事件，也不能从旧版漏记的日志反推出测速位置。`speeding_camera` 和 `avoid_sleeping` 分别保留 SDK 原始类型，不将两者互相转换。

## 校准覆盖范围与通用规则

当前配置按模型路径、挂点单位、模型内挂点编号、变体及元数据指纹匹配，不按地图探头 UID 匹配。同一配置可用于同类模型在不同位置的实例；实例的世界位置、旋转、缩放及道路关联仍然动态计算。一个地点的观察可用于初步标定，但不代表已经逐个验证了该类型的所有地图实例。

后续数据采集应覆盖不同模型、反向参数、零或非零监测距离、多个挂点、关闭挂点的变体，以及双向道路、立交、弯道和预制件。优先验证引擎挂点坐标轴、reverse_direction 和 measurement_distance 的统一语义，再制定按挂点类型复用的规则；模型配置用于例外，实例坐标用于运行时道路匹配。

单一角度或距离阈值无法修正坐标轴翻转、对向车道误关联等语义错误。参数应在独立样本上验证，不通过不断放宽阈值来迁就误报；新的资源格式或无法消除的歧义仍暂停该目标预警。

## 可选的实验标定文件

[ETS2 1.62 芬兰测速模型配置](calibration-profiles/ets2-1.62-finland.json) 覆盖模型 /model2/speedcamera/balt/speedcamera_01_fi.pmd 的 default 变体、speedcam.20 挂点和指定资源指纹。依据为一次方向吻合的测速罚款及现场资源数据；反向通行是否不触发、其他地图实例是否一致仍需实测。

[ETS2 1.62 德国三车道龙门架测速模型配置](calibration-profiles/ets2-1.62-germany-gantry.json) 覆盖 3lane_speedlimit_100_no_overtaking_trucks_60_sc.pmd 的 default 变体及指定指纹。依据为一处顺向测速罚款和另一处相反朝向模型的无罚款通过样本。后者的轨迹未进入计算出的 8 米监测邻域，因此不能据此单独证明同一探头反向绝不测速；其他变体和指纹不自动启用。

使用时将其中 entries 的记录合并到宿主 Settings/LinkEts2Nav.CameraCalibrations.json 的 entries 数组，保留已有其他模型记录。不要添加重复键。插件会自动重新读取配置，无需重启。该文件不会自动启用，也不为其他指纹或变体提供兜底。
