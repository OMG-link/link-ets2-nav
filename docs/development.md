# 开发指南

## 环境

Windows x64、Git、.NET 10 SDK、Bun。推荐使用 VS Code 和 C# Dev Kit。

```powershell
winget install --id Microsoft.DotNet.SDK.10 --exact --source winget
code --install-extension ms-dotnettools.csdevkit
```

安装后重新打开终端，使用 `git --version`、`dotnet --list-sdks` 和 `bun --version` 检查命令是否可用。

## 构建和运行

在仓库根目录执行：

```powershell
git submodule update --init --recursive --depth 1
.\scripts\dev.ps1 -Action Check
.\scripts\dev.ps1 -Action Restore
.\scripts\dev.ps1 -Action Build
.\scripts\dev.ps1 -Action Run
```

`Deploy` 构建并复制插件到开发宿主的 `Plugins/`；`Run` 在此基础上启动宿主。VS Code 的 `Nav:` 任务提供相同入口，F5 构建部署后启动调试。重新部署前卸载正在运行的插件，避免文件被锁定。

## 工程结构

- `Plugins/LinkEts2Nav/`：插件源码，ID 为 `link.ets2.nav`。
- `ETS2LA/`：固定提交的框架子模块，包含 TruckLib 子模块。
- `scripts/dev.ps1`：环境检查、恢复依赖、构建部署与运行。
- `Directory.Build.targets`、`dev-host/prepare-local-host.ps1`、`dev-host/ui/`：本地开发宿主覆盖层。
- `tests/LinkEts2Nav.UnitTests/`：xUnit 单元测试项目，为导航算法与预警规则预留。
- `tests/DevHost.IntegrationTests/`：xUnit 宿主集成测试，检查插件白名单、安装限制和页面渲染。

## 开发宿主

本地覆盖层屏蔽远程插件目录及安装，仅加载 `LinkEts2Nav.dll`，并替换首页、启动页和插件目录页。辅助驾驶的快捷键注册、状态操作和游戏控制输出已禁用；地图、遥测、路线和预警音频仍可使用。不删除用户已有插件或设置；它不是安全沙箱，也不代表禁用了宿主的全部联网功能。

覆盖源码生成在忽略提交的 `artifacts/host-overrides/`，不直接修改子模块实现。更新上游后如源码锚点检查失败，应核对接口再适配。只发布插件 DLL 时不携带这些宿主限制。

```powershell
dotnet test LinkEts2Nav.slnx
# 或使用开发脚本与 VS Code 的 Nav: Test 任务
.\scripts\dev.ps1 -Action Test
```

开发宿主输出目录为 `ETS2LA/ETS2LA/bin/Debug/net10.0`。子模块的浅克隆可能使开发版本号与官方发行号不同；需要完整历史时可在对应子模块运行 `git fetch --unshallow`。

## 测试约定

使用 xUnit.net v3 3.2.2，通过 VSTest 适配器运行，可使用 `dotnet test` 与 VS Code 测试面板；依赖由 NuGet 恢复，无需系统级安装。测试项目不随插件部署。

测试入口使用 `tests/Tests.slnx`，只构建两类测试及其实际依赖，不构建宿主主程序或地图检查工具。默认 `Test` 仍执行全部单元测试和集成测试；日常按改动范围选择：

```powershell
# 插件算法、地图匹配、语音规则
.\scripts\dev.ps1 -Action Test -TestScope Unit
# 开发宿主覆盖、插件加载、页面行为
.\scripts\dev.ps1 -Action Test -TestScope Integration
# 依赖已恢复，只重建并执行本次相关用例
.\scripts\dev.ps1 -Action Test -TestScope Unit -NoRestore -TestFilter 'FullyQualifiedName~JunctionNavigationTests|FullyQualifiedName~NavigationInstructionPolicyTests'
# 源码未变，仅重跑已有测试产物；不会重新构建，也不会恢复依赖
.\scripts\dev.ps1 -Action Test -TestScope Unit -NoBuild -TestFilter 'FullyQualifiedName~NavigationInstructionPolicyTests'
# 变更影响广泛或明确要求时的全量验证
.\scripts\dev.ps1 -Action Test
```

`TestFilter` 使用 `dotnet test --filter` 的语法。改过源码后应保留构建；`NoBuild` 只用于重跑已构建的同配置产物，不能用于验证新代码。首次运行、依赖或 SDK／上游版本变更后不要跳过恢复。单元测试入口不需要 Bun；集成测试涉及 UI 构建时仍需要。算法修改运行相关单元测试，涉及宿主覆盖时补集成测试；只有变更影响广泛、失败证据或明确要求时才扩大到全量入口。

宿主集成测试禁止并行执行，诱饵文件仅创建于测试输出目录并在结束时清理。插件测试产物由 MSBuild 自动复制，不需要手工指定宿主路径。页面测试使用 Blazor HtmlRenderer。

单元测试覆盖预警状态机、路线与道路匹配、遥测时效、真实资源格式的合成样本以及官方归档选择。测试不依赖本机安装游戏，不播放真实音频。

## 上游诊断

根目录 `Directory.Build.targets` 默认屏蔽 ETS2LA 子模块项目中已确认的编译警告，以及四条已知上游依赖漏洞公告的诊断。插件和测试源码的编译诊断、新增漏洞公告仍然保留。屏蔽不会修复漏洞，也不改变实际依赖版本。

需要审查完整诊断时，执行以下命令；恢复依赖和构建都必须传入开关，避免使用此前缓存的审计结果：

```powershell
dotnet restore LinkEts2Nav.slnx -p:NavShowUpstreamWarnings=true
dotnet build LinkEts2Nav.slnx --no-restore --no-incremental -p:NavShowUpstreamWarnings=true
```

恢复默认显示策略后，运行 `dotnet restore LinkEts2Nav.slnx` 刷新依赖诊断。上游更新时应重新审查并移除不再需要的屏蔽项。
## 地图资源检查

`tools/LinkEts2Nav.Probe/` 是开发用只读工具，不随插件发布。它读取本机游戏归档，不启动游戏，不修改存档；JSON 输出可重定向到忽略的 `artifacts/`。普通扫描必须提供世界坐标。

```powershell
dotnet run --project tools/LinkEts2Nav.Probe -- --game-path "<game-directory>" --x -39000 --z -30000 --radius 1000
# 检查指定模型的真实测速挂点
dotnet run --project tools/LinkEts2Nav.Probe -- --game-path "<game-directory>" --inspect-model /model/speedcamera/speedcamera_hw_au.pmg
```

默认扫描已安装官方归档，输出的 `profileResolved` 为 false，不代表当前存档。传入 `--game-log "<game.log.txt>"` 后才按实际挂载日志解析当前地图；会拒绝无法确认兼容的地图或探头资源覆盖。模组以最近一次显式活动列表为准；模组管理界面的临时预览挂载不算启用，也不会重置地图缓存。用 `--help` 查看完整参数。

启用插件后，开发宿主首页的“测速探头诊断”链接进入 `/link-ets2-nav`。该页面随插件 DLL 提供，在标准宿主中也可通过对应路由访问。架构及预警规则见 [预警设计](architecture.md)。
## 运行日志

插件日志统一带 `[LinkEts2Nav]` 前缀。加载日志不代表插件已经启用：在插件管理器中启用后，还应看到“插件已启用”和“后台扫描已启动”。日志包含等待遥测、暂停、数据过期、地图挂载、扫描结果、校准配置、发现目标、判定变化及预警播放请求。

扫描与归档读取在独立后台任务中执行，不阻塞已准备地图上的预警判定；刷新期间诊断状态显示“使用已准备快照”。首次扫描仍需等待完成，未加载区域中的目标不会凭空推断。刷新失败保留已有快照并间隔重试，传送或地图来源变化则立即清除旧快照。

相同状态和扫描结果每 30 秒汇总一次；探头距离变化不会逐帧刷屏，方向或判定改变则立即记录。目标离开诊断列表不等于已经过测速位置。日志中的播放请求也不等于音频设备已实际发声，音频失败会另有警告。直线距离回退时，目标判定日志附带“已知路线长度下限”；这是缺失几何情况下的保守下限，不是完整沿路距离，预警不会早于该下限允许的阶段。

从仓库根目录观察日志：

```powershell
Get-Content .\ETS2LA\ETS2LA\bin\Debug\net10.0\ets2la.log -Tail 30 -Wait
```

插件运行日志附带 UTC 时间；宿主控制台另有本地时间。上游文件日志约每 5 秒刷新一次，因此文件输出可能比控制台稍晚。重新启动宿主会重新创建日志文件，需要保留时请先复制到本地忽略的 `artifacts/`。

## 模组兼容性检查

兼容性检查按实际资源文件判断：车流生成规则、AI 车道规则和信号灯时序允许共存；收费站配置仅在解析确认全部单位为收费站或非测速模型挂点、且没有外部包含时放行。真正覆盖道路、模型、标志或测速挂点的文件仍会暂停扫描，日志会列出完整模组路径和冲突资源。

## 预警音频与试听

测速诊断页的“试听预警音”按钮仅测试声音链路，不计作探头预警，也不需要启用扫描。可先保持游戏暂停，启用插件并等待日志出现“附近地图已准备”，再开始行驶，减少首次资源加载导致的预警延迟。

在宿主输出目录的 `Settings/LinkEts2Nav.Audio.json` 中选择本地音频：

```json
{
  "filePath": "Assets/LinkEts2Nav/community-radar-preview.wav"
}
```

相对路径以宿主输出目录为基准，也可使用绝对路径。配置在每次播放请求时读取，修改 JSON 无需重启；更新 DLL 仍需重启宿主。支持 WAV、OGG、MP3、FLAC；FMOD `.bank` 须先解码成普通音频。配置缺失时使用内置提示音，配置或文件错误会记录原因并尝试回退。

借用第三方声音进行本地测试时，音频和提取工具应放在忽略目录，不能随插件 DLL 或代码提交分发。试听和实际预警都会记录选用的音频文件；“已提交播放”只表示已排队，设备或异步解码错误需结合宿主音频日志判断。

## 离线语音合成

可选的 `tools/LinkEts2Nav.Speech/` 是常驻 .NET 合成子进程，使用 sherpa-onnx 2.0.1、CPU 推理和 Kokoro multi-lang v1.1-zh。当前预设音色为 `zf_067`（该模型 Speaker 36），默认使用 2 个线程。开发脚本自动构建并将 Windows x64 worker 及原生依赖部署到宿主的 `Tools/LinkEts2Nav.Speech/`；无需安装 Python、CUDA 或系统语音服务。

模型需另行下载并解压：[官方模型包](https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/kokoro-multi-lang-v1_1.tar.bz2)。模型权重、音色、词典和生成音频不提交到代码仓库。模型与运行库各自保留原有许可证；[Kokoro 模型说明](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)和[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)提供来源及许可证。

在宿主输出目录创建 `Settings/LinkEts2Nav.Speech.json`：

```json
{
  "enabled": true,
  "modelDirectory": "Models/kokoro-multi-lang-v1_1",
  "workerPath": "Tools/LinkEts2Nav.Speech/LinkEts2Nav.Speech.dll",
  "cacheDirectory": "Cache/LinkEts2Nav/Speech",
  "voice": "zf_067",
  "threads": 2
}
```

相对路径均以宿主输出目录为基准，也可配置绝对路径。配置缺失或 `enabled=false` 时继续使用已有音频。TTS 配置在启用插件时读取；修改后停用再启用，更新 DLL 后需重启宿主。模型目录必须包含 `model.onnx`、`voices.bin`、`tokens.txt`、`lexicon-zh.txt` 和 `lexicon-us-en.txt`。

默认文案为“五百米处，有测速照相。”和“两百米处，有测速照相。”；只有本次接近首次确认目标时距离已小于 200 米，才只播放“两百米内，有测速照相。”。正常经过 200 米阈值时，即使采样距离略低于 200 米，仍使用“两百米处”。迟发现但仍超过 200 米时使用“前方有测速照相。”。实验限速解析能确认结果时附加“限速五十”等文案；未知时仍不附加。遥测中的当前位置限速只用于实测核对，不能直接代替前方探头限速。

确认目标在前方后，立即按各语音触发点的预计顺序准备完整短句，包含未来动作和可能因触发时车速而跳过的 100 米档。相同文案共用文件缓存；缓存损坏会重新合成。预生成音频包在启用时预载并校验。运行时触发只将条目交给独立播放管理器，尚未完成合成时继续保留，不立即用提示音替代；合成失败或未启用 TTS 时才回退提示音。待播语音比远期预生成任务优先准备。

播放管理器优先选择执行指示，其余距离预告同级；前一音频真正播放完成后再选择下一条。同一事件后续阶段可以覆盖尚未播放的前一阶段，其余语音不会仅因等待较久被丢弃。暂停保留队列并停止开始下一条，当前音频允许播完；读档、传送和关闭插件清空队列。路线重算只撤销旧路线独有的前方事件，保留共有事件。诊断页的“试听预警音”继续独立试听 `LinkEts2Nav.Audio.json` 指定的音频，不参与导航触发状态。

## 远端预生成与本地拼接

提供商无关的文本任务导出、外部音频导入和城市名清单提取见 [自制预生成语音包](speech-packs.md)。Qwen 仅是可选适配器，运行时的 `packDirectory` 不限制来源。

Qwen 音频包只在开发者主动运行生成命令时联网；插件运行时不会读取 API 密钥，也不会调用远端服务。使用 `qwen-audio-3.1-tts-flash`、`longanhuan_v3.1` 和 [Qwen WebSocket 协议](https://help.aliyun.com/en/model-studio/qwen-audio-tts-websocket-api)。生成会产生服务商计费。

在仓库根目录的 `.api-keys` 中写入 `qwen=你的密钥`。该文件被 Git 忽略，不复制到宿主或发布目录。随后执行：

```powershell
dotnet run --project tools/LinkEts2Nav.Speech -- --generate-pack --keys .api-keys --output artifacts/speech/qwen-longanhuan-v3.1
```

命令生成 127 个音频文件：500 米处、200 米处、200 米内和前方四种整句，各有无限速版本及限速 30、40、50、60、70、80、90、100 的版本，共 36 句，加上未校准探头接近提醒整句及长直路兜底提示和 84 条基础导航指令；另有五个模板片段：“米处，有测速照相。”“米处，有测速照相，限速”“米内，有测速照相。”“米内，有测速照相，限速”“前方有测速照相，限速”。限速播报不带“公里”。每条成功后保存清单和 SHA-256；重复执行复用已验证的文件，不重复调用服务。生成异常时停止，修复后可重新执行。更换模型、音色或合成参数时应生成到新的目录，避免混用不同音频包。

`Deploy`/`Run` 会将上述本地生成目录复制到宿主 `Assets/LinkEts2Nav/SpeechPack/`。也可手动复制整包，并在 `LinkEts2Nav.Speech.json` 中设置 `packDirectory`；默认值即该相对路径。音频和清单存放在忽略的产物目录，不随源码提交。自行分发音频包前须确认生成服务的相关授权。

匹配完整文案时优先使用音频包。遇到特殊数字，例如“五百米处，有测速照相，限速六十五。”，则由本地 Kokoro 分别生成“五百”和“六十五”，再依次拼接远端模板片段，保存完整 WAV。两种来源统一为 24 kHz、单声道、16 位 PCM；拼接的是采样数据，保留原有停顿，音色接缝可能明显。没有可用模板、文案不匹配或音频包损坏时回退本地整句合成。缓存键包含模板及本地数字音频内容，内容变更后不会误用旧拼接音频。

实验解析器提供的探头限速会选择对应文案；无法解析时使用不含限速版本。带限速语音未准备好时保留待播项并优先合成；排队期间限速估算变化会更新对应文本，不回退成另一条距离语句。可通过 worker JSON 输入离线测试特殊限速文案，无需启动游戏：

```powershell
dotnet run --project tools/LinkEts2Nav.Speech -- --model-dir "<model-directory>" --cache-dir "artifacts/speech/cache" --pack-dir "artifacts/speech/qwen-longanhuan-v3.1"
```

输入 `{"id":"special","text":"五百米处，有测速照相，限速六十五。"}`，返回完整缓存 WAV 路径；重复输入复用本地数字和完整拼接缓存。工具不会自动播放音频。


运动判定采样保存在宿主输出目录的 `Cache/LinkEts2Nav/Diagnostics/motion.jsonl`，上一段为 `motion.previous.jsonl`。每段约 8 MiB，最多保留两段；重启宿主也会轮换。采样记录每次预警判定实际使用的位置、朝向、时间、路线状态、资源标识、区块、已校准探头和判定结果。路线节点内容未改变时省略 `Route.Nodes`，回放时沿用同文件上一条非空节点列表；每段首条记录始终包含节点。`Sequence` 跳号表示异步写入队列满时丢失了采样，不能当作连续轨迹。文件写入失败只关闭采样，不中断预警。它用于重放插件判定输入，不是游戏录像；重建道路几何仍需对应版本的游戏地图资源。这些文件含本机安装路径和行驶位置，位于忽略的产物目录，不随源码提交。

未校准且挂点部件有效的探头按挂点位置的直线距离在 500 米内提醒一次，不使用导航方向判定，也不附加限速或 200 米阶段。首次发现已在 500 米内时立即提醒。预生成包包含完整固定文案；扫描刷新或目标临时消失不重置去重状态，经过附近并离开至少 50 米后再次接近可重新提醒。暂停、过期车辆数据及倒车期间不触发。

限速解析按道路／预制件的实际连通关系传播国家信息：普通共享节点连接分量，国界节点将两侧分开，并分别使用对应地图条目的国家 ID；ID 对应名称取自当前挂载的国家定义。城市区域只能给实际位于区域内的道路提供国家依据，不作为整份附近地图的默认国家。多个国家出现在同一批区块时不会影响互不相连的道路。没有可达依据、国家 ID 未知或证据冲突时继续返回未知；该索引在后台扫描已有区块时构建，不额外读取整张地图。

## 导航事件与播放规划

基础导航沿用 SDK 当前路线，以连续道路路径的弧长计算动作距离。路口动作使用 PPD 原生曲线起止旋转提供的世界空间切线，不使用相邻道路采样方向替代。普通角度动作只适用于已确认交叉路口，加减速车道按完整车道段另外识别。环岛使用识别出的环体及接口排序，另有特殊结构定义库。

普通道路分流独立于交叉路口规则：按同一入口可到达的出口接口分组，完整遍历 PPD 原生路线，在分支已确定后的曲线链上收集转向灯指令，忽略共用进路的灯光和末端清灯。所选分支单向打灯时提示向左／右前方行驶；唯一无灯分支作为主路延续静默；多个无灯分支按真实继承的入口车道集合提示选道。车道次序在入口按原生车道端点排序，不将不同接口的车道编号直接视为同一车道。灯光冲突、缺少继承关系或无法用入口车道集合区别出口时记录“道路分流未定”，不以角度猜测。

普通分流默认以实际分流预制件入口为动作锚点，进入该预制件后结束。已证明的减速车道则要求完整的“原生共同前缀分出附加车道—同向车道组并行不超过500米—附加车道走向独立出口”结构。完整原生路径的灯光区分新增侧车道与原保留车道；留在原主路时静默，驶向附加车道时在其开放处到分离接口的从起点向终点行驶10%的沿路位置设置动作。结束点仍为分流接口。真正的多个无灯主路分叉保留入口车道集合提示。

加速车道采用这一结构的反向对称判据：一端为真实共享车道，不超过500米的同组并行段另一端必须有独立入口等原生分离依据。仅有几何上的短距离靠拢不足以判成加速车道。对于入口、出口兼用的附加车道，当前导航不采用的出口只在局部导航约束视图中视为不可行驶；若附加车道无法独立到达指定道路，而原主车道仍可达，则确认为必须并线，不改物理地图。独立入口的车道先逐段沿原生继承追踪到最终合并或本次导航分离接口，不能因规划器提前安排合法换道而丢失该动作。动作锚点为完整可执行段的从起点向终点行驶10%的沿路位置，结束点为真实合并点或导航分离接口。距离预告及20米执行提示沿用统一触发规则，相对该10%位置放置。

车道段区间与语音位置分别由 `LaneActionInterval` 和各类动作表示，`ApproachInterval` 在诊断中保留真实起止距离。证明和完整灯光信息在已有地图几何构建中提取，不增加磁盘读取；搜索临时状态随单次构建释放。跨帧只保留当前路线仍包含的车道段与起止里程，以支持 SDK 移除已行驶的路线前缀；新地图事实证明旧选道事件其实是主路延续时，使用既有系列结束机制撤销尚未播放的旧提示。

环岛接口只依据成员区域自身的原生边界提取：成员预制件及成员普通道路之间共享的节点属于内部连接，其余有向输入、输出节点分别形成入口、出口，同一接口多车道合为一个端口。每个方向各取真实车道端点，以代表环的统一圆心和通行方向计算极角；不要求端口能连接代表环，不枚举其他车道环，也不依赖外部预制件。普通道路只使用已确认可通行的方向。端口身份与行驶定位分开：原生图为每个出口保存专属驶出分支及真实输出曲线起点，所选导航路径按曲线编号定位实际驶出沿程，再计算到边界的连接距离；途经但未选中的出口沿该路径有序投影。区块仍只进行一次自动闭环构建，搜索缓存随该次构建释放。

生产流程按以下职责分工：

- `NavigationRuntime` 从已确认路径收集有序动作；`WarningPipeline` 确认探头归属、方向、接近轮次与动态限速，二者不直接播放。
- `NavigationEventPlanner` 将全部已确认动作展开为事件及上游触发点。首条简报在规划时安插于前一导航动作的真实结束位置，距离文案由该位置到下一动作的位置计算并固定；后续触发不依赖当前动作选择。直行保留为结构事件，不进入导航动作前驱链，也不参与“然后”拼接；序号直行提示与密集链提示属于独立的动作辅助语系列，仍使用统一触发点和物理结束点。
- `RouteProgressTracker` 在 SDK 截短路线前缀后对齐路线坐标，`GuidanceTimeline` 发布事件和触发点，并保留刚跨过、已经离开动作识别结果的执行点。
- `SpeechTriggerScheduler` 消费到期触发点，记录已入队、静默、车速跳过及被后续阶段覆盖的状态。`GuidanceCoordinator` 统一处理来源发布、会话、重算、准备及入队。
- `SpeechAnnouncementQueue` 负责音频合成和文件缓存，`GuidancePlaybackManager` 负责待播队列及优先级，`Ets2LaGuidanceAudioPlayer` 通过宿主公开音频队列回调等待真实播放完成。

第一层简报与长路段继续行驶提示互斥：可见的下一非直行动作在 2000 米内时给出动作预告，否则只说明继续行驶距离；可见范围内没有非直行动作时使用不带距离的沿当前道路提示，包括地图尾部尚未加载的情况。超过 1000 米按 100 米、超过 10 公里按 1 公里向下取整。从一公里起使用公里，中文读法包括“两公里”“两百米”“一点二公里”“二点一公里”。同一动作首次规划时固定首条触发点与文案，不在离开前一路口的某一采样帧重新取整。

固定距离档位为 2000／1000／500／200／100 米，20 米为独立执行档位。首次在两档之间发现动作时，按原始距离与两档中点的关系归属档位：达到中点时把较远档延后，否则把较近档提前，后续保留更近档。例如首次 388 米归 500 米档，报 350 米并保留 200 米；首次 300 米归提前的 200 米档，报 300 米并在此统计路口序号，不再重复 200 米。文案距离单独取整，归属档位的路口计数、近端文案及速度条件仍适用。首次 50～100 米归延后的 100 米档，初次 25 米等待 20 米执行，初次不足 20 米立即执行。100 米档触发当时车速达到 60 km/h 就跳过该档，但仍提前准备其音频；独立执行区间不受档位归属或速度过滤影响。执行提示可附加不足 100 米的下一动作，例如“左转，然后六十米左转。”，后一个动作仍有独立执行点。

非直行路口动作在 200 米档的实际触发点统计该点至动作点间的非次要路口，包含目标路口，用第几个路口说明目标；该档提前或延后时，计数起点随之移动。首报归 500 米档时先报距离与动作，归 200 米档时直接附加序号，归 100 米档时不补造已略过的计数语义。计数区间内的直行路口播报“直行通过第x个路口”；500 米档实际触发点至计数点间的直行路口播报“直行通过当前路口”，不参与该动作的序号。两种通过提示都在入口前约两秒或 20 米处（取较早者）触发，首次已不足 20 米则立即提示，并在路口通过后结束。目的地等非路口目标不使用路口序号，但其前方 500 米内真实经过的路口仍可产生无编号辅助提示。已被这些辅助提示覆盖的路口不参与密集链；其余非次要直行路口（含匝道口）按入口间距不足 200 米构成最大链，至少三个时在首口前 200 米产生一次密集辅助提示，结束于倒数第三口末端。密集辅助仅在固定 200 米点播报，首次已错过该点、该点早于前一非直行动作结束点或该结束点未知时不补播。辅助语不进入导航动作前驱链，环境事件也不影响该链。

接口是否有效按其所有原生输入、输出车道端点中最外侧两点的水平间距判断，至少 3 米有效。对于交叉路口，只有本次直行入口、出口有效且没有其他有效接口时，本次通过为次要路口；从无效接口直行到另一无效接口仍按普通路口处理。交叉路口与无交叉的多接口匝道口在代码中区分，对用户统称路口。匝道口还要求本次行驶入口具有至少两个可达的物理出口接口；对向出口或同一接口的多条车道不增加该数量。只有满足本向选择条件的匝道口参与计数和密集链，单出口汇入不计作路口，但独立的并线动作检测仍保留。

环岛预告为“距离后，进入环岛”，100／20 米附加出口编号；入环后每个出口前约 20 米提示经过出口或驶出环岛。测速事件按同一模型提供 500／200 米普通预告，不包含 100／20 米档位。同类环境事件以先前事件的真实结束位置约束首条预告，不同类环境事件及导航动作互不阻挡；首次可播距离不足 500 米时，按 50 米向下取整即时提示，原始距离达到 350 米则保留 200 米档，否则跳过，低于 50 米时不读出零米。无导航时仍可沿唯一必经路径进行测速预警。

已校准测速和车道变窄分别拥有同类前驱链。未校准探头仍是独立的固定接近提醒，不具已确认的道路顺序或监测边界，不作为后续已校准测速或其他未知提醒的前驱。无可用沿路坐标时，直线距离回退仍保留已知道路长度下限约束；前一测速点的结束位置未知时，后续同类首条预告等待有向通过事实补齐，不能提前构造结束点。

导航动作和环境事件分别规划前驱链；后者不会改变导航首条简报的位置。同次环岛的进入预告、进入执行与环内出口提示共用一个语音系列，后续出口提示可覆盖尚未播放的入环或早出口提示。系列按物理组件、入口接口和本次沿路入口位置识别，同次更改所选出口不拆分系列，再次绕回则建立新的系列。路口系列结束于所选预制件路径末端，环岛系列结束于整个组件的对外出口，测速系列结束于监测点通过事实。结束点与语音点按沿路顺序消费，严格越过结束位置后在同一原子队列批次取消该系列待播项，不使用按年龄淘汰或额外结束墓碑；已开始的片段允许播完。未知结束位置等待数据补充，不将动作开始位置当成结束位置。

诊断页显示完整事件数、触发点、待播内容及最近触发结果。`motion.jsonl` 中的 `Guidance` 字段包含同一诊断。`NavigationInstructionPolicy` 为旧同步接口提供薄适配器，直接复用同一 `NavigationEventPlanner`、`GuidanceTimeline` 和 `SpeechTriggerScheduler`；仅负责将相对距离样本对齐为路线坐标、检查新鲜度和适配音频就绪回调，不另维护直行或转向的触发阶段策略。宿主生产路径始终传入统一 coordinator，由播放管理器选择音频。

## 导航生命周期与城区提醒

`GuidanceNotification` 表达导航开始与路线重算等即时事实，不是空间播报系列，因此不要求人为设置结束点。这是空间系列结束点约束的明确例外；普通导航及环境预告仍必须附带真实结束点。通知复用 `GuidancePlaybackManager` 的优先级、缓存、暂停及会话重置，优先级为 5（执行提示为 0，普通预告为 10），不另开音频播放器，也不打断正在播放的片段。宿主元数据准备后即可提供行程估算，通知不必等待附近区块扫描。

`NavigationJourneyTracker` 仅观察新鲜且正在推进的遥测与有效路线。正常 SDK 路线前缀裁剪、尾部扩展复用 `RouteContinuity` 判断；完整终端节点改变与其他非连续替换统一生成重算请求，连续变化在五秒内仅提示一次。数据无偏航原因标志，不根据地图匹配失败声称偏航。行程概览直接累计当前 SDK 路线首个接口至终点的道路长度与预制件校正弦长，不依赖玩家位置、朝向或道路匹配，也不扣除首段已行驶部分。开始和重算通知等完整行程估算就绪后才入队，每个请求成功估算一次；失败记录原因，五秒后重试。路线关闭且 SDK 剩余归零时清理导航及城区系列，不另播到达确认。

`RouteJourneyEstimator` 沿完整 SDK 路线的物理节点引用复用宿主 `Road`／`Prefab`。普通道路取已存储的 `Road.Length`；预制件始终取入口、出口控制节点的三维直线距离并乘 `JourneyEstimationCalibration.PrefabDistanceFactor`，不读取全程 PPD 或重新扫描区块。统一系数为 1.028：八区域离线最短时间路由的 4,800 条完整路线、295,026 次预制件通行中，原生曲线累计长度与控制接口直线累计长度之比为 1.0278627098，按累计长度及路线经过频率加权，不取各通行比值的算术平均，也不包含人为参考线接缝。这是粗估校准样本，并非官方全图真实交通分布。SDK 中间未识别 UID 只在首尾同属一个预制件且不跨越其他已知道路边界时合并为一次通行；连接或终端不完整则返回未就绪。SDK 距离只用于校验节点顺序与完整终端，不参与世界距离换算；不做玩家位置匹配或首段投影。同一道路重复经过时按路线中的每次通行分别累计。

估算速度复用已预热 `SpeedLimitDefinitionReader.RoadCategoryLimit` 的国家货车道路类别限速，不加入标牌或区域限速；预制件沿路线借用两侧最近普通道路中较低的类别限速，单侧已知时使用该侧。现实时间为驾驶段 `世界米数 / (类别限速 × 0.8 / 3.6)` 之和，再对每次已确认的轮渡连接增加60秒，轮渡距离为0。`FerryJourneyIndex` 在全局准备阶段复用宿主港口对象及其预制件接口，读取 `/def/ferry/connection/` 中的明确港口连接；每次查询只查该索引，不按空间距离猜测海路。港口陆路仍正常计入，预制件不会跨轮渡借用另一岸道路限速。缺少剩余路段的类别限速时不猜测时间，SDK 的缩放距离和剩余游戏时间都不作为替代值。

`NavigationDestination` 只在非截断 SDK 路线的零距离终端 UID 与已确认连续世界路径末端一致时生成终点动作，距离采用该路径的世界弧长。终端缺失或处于货场自由行驶区域时不编造距离。终点沿用普通预告／20 米执行及前驱结束规则，不当作第几个路口；预告“到达目的地”，执行提示“到达目的地附近，导航结束”。

`CityEntryEventBuilder` 沿已确认的定向导航连接读取快照 `SignProjections`，仅以可靠的 `Urban=true` 标牌生成 `city-entry` 环境事件；不再使用 Area 边界生成入口。`Urban=false` 只更新城区状态；模板、方向、归属或规则未确认的标牌不播报，并使该处之后的推演状态未知。实例只保留已经实际经过的最近城区状态，未来路线在局部副本上推演，因此地图窗口滑动不会把连续的入城牌重新当作入口。会话重置清空状态，仅路线坐标变换则保留实际状态并重定位沿程锚点。优先使用扫描器的现成投影索引；没有索引时以 `SpeedLimitData` 与完整 PPD 路径集合的引用为键复用一次补建结果。标牌缓存点按当前路线重新投影，避免采样密度不同导致触发距离偏移。运行时使用独立 `EnvironmentPreviewPlanner` 和同一全局路线坐标，复用 500／200 米及首次短距离规则，实际经过标牌的位置即结束点；不构成导航动作前驱，也不与测速或车道变窄共用同类链。

## 导出预制件导航线路 SVG

无需启动游戏即可从本机官方游戏资源读取 PPD，输出真实几何、方向箭头、曲线索引、原始后继表，以及各入口车道可达的出口车道：

首次使用或导出工具源码变更后正常执行；后续可添加 `-NoBuild` 复用已有构建产物。可选 `-GameLog "<game.log.txt>"` 按日志选择官方归档与支持的启用模组检查。工具不启动宿主、不安装 DLL。

图中数字是预制件内的原始 `NavCurve` 索引；入口/出口表使用原始控制节点编号和车道槽位，均从 0 开始。颜色表示能到达该曲线的入口节点，多入口共享曲线使用紫色。曲线采用原始位置、旋转和长度重建，整体保持 XZ 比例；控制节点参考点、曲线交叉均不意味着存在车道连接，以 `NextLines` 和可达表为准。可达性表示存在某条内部路径，可能经过环路，不自动代表允许直接横向换道。


## 车道合并与虚拟换道

无冲突汇合由 `RoadJoinTopology.IndependentEntries` 单独识别：至少两个入口，各入口车道一一保留，仅有同一个出口，入口之间的出口车道集合互不相交。只有此类结构使用 `RoadJoinPriorityScorer`；存在共享出口车道的真实并线不使用评分。坡度、方向、车道数各分配 10 分：坡度权重为 `1/max(坡角差绝对值,0.1°)`，方向权重为 `1/max(水平角差绝对值,0.5°)`，车道权重为入口车道数，每项按所有入口权重归一分配，左侧偏好为 0。最高分必须领先每个其他入口至少 5 分（等于 5 接受）才确定主路。任一入口缺少必要数据时，保留全部竞争者且不判定主路；优势不足亦保留未知。

`RoadPathSource` 为当前已加载的预制件快照附加 `DirectedRoad.JoinPriority`，由接近及已经进入预制件的两处 `RoadJoinClassifier` 调用共同使用。方向取原生入口／出口切线的水平夹角；纵坡取关联 `Road.InterpolateCurve` 的真实世界曲线，采入口前末 20 米及出口后首 20 米的升高量／水平里程坡角，约每 0.5 米采样。窗口不足时仅沿唯一相连的已加载普通道路延伸；不把预制件控制节点到车道端点的人为连接段计入坡度。道路窗口按节点与方向在本次快照构建中复用，评分随新快照重建，不读取额外地图文件。`无冲突汇合主路评分` 日志保留每项得分、主路领先分或缺失原因；可从 `JoinPriority.Measurements/Scores` 检查完整竞争集合。确定的主路标为 `Continuing`，其他入口仍走既有 `Entering` 处理；未定保留原有未知连接屏障。

车道路线继续使用官方物理节点作为入口、出口约束，预制件内部路径保留原始曲线索引。算路优先减少跨越相邻车道的总次数，再比较路径长度；跨两条车道计两次，不额外计算一个重复的横向切换量。当前位置用于约束当前车道，位置变化导致车道归属变化时重新选路。普通道路上的车道切换、以及直接相接且平行的车道端口之间，可使用明确标记的虚拟换道连接；它不是原始 `NextLines`，也不代表已解析道路标线许可，不用于车辆控制。

`LaneMergeDetector` 先由共享后继曲线确认合并，再由 `MergeBlinkerDirection` 检查共同后缀前的两条竞争曲线：一侧为 `Left/Right`、另一侧为 `NoBlinker/NoBlinkerForced` 时，前者为并入车道，后者为延续路线。`PrefabPathGeometry` 将每段 PPD 原生转向灯指令与 `CurveIndices` 一一保存；读取紧邻本次合流的竞争段，不使用整条链上更早的转向灯或共同下游的灯光。同灯、双灯、缺失及灯光与车道侧向位置矛盾时，诊断保留 `Uncertain`，`MoveLeft` 与主次车道字段为 `null`，不产生带方向的合并动作，也不以曲率兜底。角色判定不依赖上游入口来源。之后沿两条真实车道的几何历史测量平行接近区间：以约 1° 的切向容差和相邻车道间距检查，长度包括末端收敛段，以与汇合点的距离统一。距离按 2 米采样；确认达到 500 米即可分类，无需继续寻找全长。道路上的车道位置由参考曲线及接口横向偏移重建，并非游戏直接导出的车道轨迹。

不足 500 米且已观察到平行段起点时，产生 `Silent` 动作；达到 500 米时产生 `DistancePreview` 环境事件，沿同一系列规划 500／200 米通知，不包含 100／20 米执行提示。数据范围或连接歧义导致上游长度不能确认时，诊断保留 `Uncertain`，使用静默动作防止过早结束等待。已进入本次合并接近的状态保持到驶过实际公共曲线起点，避免规划车道短暂变化导致长距离简报提前出现。已识别环岛继续由环岛导航处理，不插入独立匝道合并动作。车道通知结束位置使用原生共享下游曲线起点的沿路投影，即侧向车道实际合并完成处，不能用提前预告位置或整个预制件出口替代。

`NavigationAnnouncementMode.Silent` 使用正常阶段消耗状态，但规划和执行均不产生音频文本、不调用音频就绪回调，也不触发提示音；`NoticeAt500` 只预热并执行一次固定提醒，首次发现已在 500 米内时立即尝试播报。`NavigationDiagnostic.LaneMerges` 和“车道合并判定”日志保存侧别、长度依据、分类与汇合点距离，可随回放分析。


## 特殊环岛定义库

`Plugins/LinkEts2Nav/Data/special-roundabouts.json` 存放经过人工核对、无法通过原生闭环算法识别的环岛。它作为嵌入资源随插件发布，不需要另装数据库服务。新增或修改定义后重新构建插件。

- `id`：定义的稳定标识，不能重复；`description` 记录资源特征。
- `members`：成员列表。`key` 是定义内的别名；`resource` 为完整 PPD 路径，`curveCount` 和 `controlNodeCount` 为预期结构。单成员可省略 `instanceUid`，匹配此资源的各个地图实例；组合的每个成员都必须填写十六进制地图 UID，防止把使用相同资源的其他路口拼在一起。
- `referenceCircuit`：按行驶方向排列的参考曲线，每项用 `member`、`curve` 定位，并以 `expectedNext` 校验该曲线原生的同对象后继。参考环用于几何中心及通行方向，不决定哪些原生接口存在；不要求参考环的闭合连接实际存在，也不会把该连接加入游戏行驶图。
- 组合可包含普通道路成员：只填 `key` 和 `instanceUid`，省略 `resource`；参考曲线编号 `-1` 表示道路 Node 到 ForwardNode，`-2` 表示反向。道路成员的 `expectedNext` 可以为 `null`，因为后继由地图接口 UID 连接。

所有成员及参考曲线加载完成后才建立特殊环岛，允许组合跨区块延迟完成。明确的特殊定义优先于自动识别结果。资源结构或校验连接变化时跳过旧定义，并在地图诊断中留下记录；地图缺少引用时仍等待补充数据。出口分组、接口匹配及出口编号沿用正常环岛的实现，不按预制件名称猜测出口。

当前包含赫尔辛基港口的 `balt_r1_x_r2_round_tram_helsinki.ppd`。其参考顺序为 `30 → 31 → 26 → 32 → 12 → 34 → 36`；最后回到 30 仅表示参考顺序闭合，不是新增的车道连接。


## 交叉路口与角度指引范围

`PrefabJunctionClassifier` 复用 PPD 的 `Intersections`，不再按采样曲线求几何交点。入口、出口按具有有效 InputLines、OutputLines 的控制接口计数，而不是车道数量。只有至少两个入口、两个出口，并存在不同入口、不同出口之间的横向交叉组，才设置 `PrefabJunctionInfo.IsJunction`。

标志依据 [SCS Blender Tools 的 PIF 定义](https://github.com/SCSSoftware/BlenderTools/blob/master/addon/io_scs_tools/consts.py)：记录组头中的 `0xF0` 表示组大小，`0x10000` 是分流、`0x20000` 是汇合；两类均排除。`0x40000` 的尖角交叉仍属于交叉。组内曲线再按原生 Next 关系追溯入口及出口，排除同入口车道交织和同出口收敛。无有效交叉记录时不猜测。

`NavigationManeuverDetector` 将全部角度分类统一为路口规则 `ClassifyJunctionAngles`：左转、右转、掉头、左右前方及直行均只在已确认交叉路口计算。普通道路节点分岔和未经确认的预制件不调用这组规则。基于车道连接结构的合并、驶出和已识别环岛仍按各自规则处理。`LaneExitApproach` 可独立从专属外侧车道及上游新增车道原生分叉生成驶出动作，不依赖被禁用的角度指引；该结构依据优先于把专属出口误当作直行的几何结果。


## 沿路径模拟临时限速

后台扫描通过 `ProjectedSignBuilder`／`SignProjector` 将标牌投影到有向道路和原生 PPD 连接上，保存标牌 ID、投影点、沿线位置及规则动作。此阶段不向其他道路传播限速，也不为合流点合并临时限速。接口处的平行曲线按共同入口／出口挂载，邻接预制件在同一有向接口上的候选属于连续道路。

`SpeedLimitResolver.ResolveToCamera` 使用当前游戏导航路径；无导航时使用已有的唯一必经路径。以 SDK 当前实际限速初始化一个临时值，只依次执行当前位置之后、探头之前的标牌事件。新数值覆盖旧数值；解除标牌一次清空临时值，不维护叠加栈。路径未连续到探头时不猜测另一支路的限速；相同探头的结果随玩家位置、导航路线和 SDK 种子重新计算，不按探头 ID 缓存。标牌缓存的世界投影点会重投影到实际路径采样线，避免两种采样密度的里程差异。

国家／道路默认值、Area 查询和国家最高限速的组合继续使用既有实现。Area 仍按所属区块缓存在 `SpeedLimitAreaCache`，查询检查最近四个区块；城市归属和城区交通规则仍分别处理。道路及 Area 的默认值在临时限速解除后继续参与计算。若种子不可用或未来标牌归属未确认，则保留未知，直到遇到明确的设置／解除标牌。

运行时停止生成、比较和记录当前位置的预估限速；车辆 SDK 实际限速仍作为路径仿真种子与回放原始遥测保存。旧回放的比较诊断字段继续兼容，但不再由预警流程填充。离线验证应选择回放前方目标点、恢复当时导航路径并模拟到该目标，而非重新启用当前位置比较监测。

### 条件区间触发

`SpeechTrigger.Window` 可指定轮询起点、回调和起点是否必须越过；`SpeechTrigger.AlongMeters` 仍为强制触发终点。`SpeechTriggerScheduler` 仅对新鲜、启用、未消费且已进入区间的触发器调用回调，传入事件、当前沿路位置、速度和时间；到达或越过终点时直接入队。回调不负责合成或播放，音频在规划后提前准备。区间不排斥其他系列，触发后使用共享播放器的优先级及系列覆盖；系列结束仍会取消待播项。回调本身不写入回放，区间边界会随诊断保存。

导航最终执行提示使用此机制：区间从该动作最早合法播报位置开始，以原20米触发点为终点；回调判断剩余沿路距离是否不超过当前速度对应的两秒车程。因此低速最迟20米触发，高速按两秒车程提前入队，且不会越过上一动作结束边界提前触发。触发后同系列较早的预告被消费，减速不会使已触发的提示重新等待。该规则决定入队时机，不保证播放器立即开口。

### 城市名独立语音片段

`CitySignNameReader` 从入城标牌模板的板面绑定、文本对象 ID 和实例文本覆盖读取原始 Unicode 城市名，多个不同文本无法确定名称时保留普通城区提示。运行时只启用启动时已校验的 `SpeechPack/CityNames` 名称，避免本地模型跳过词典外地名。

准备 UTF-8 文本文件，每行一个城市原名，再显式调用 Qwen 生成独立名称片段（使用 API 额度）：

```powershell
dotnet run --project tools/LinkEts2Nav.Speech -- --generate-city-names --keys .api-keys --output artifacts/speech/qwen-longanhuan-v3.1/CityNames --texts city-names.txt
```

工具保留并复用已有校验通过的名称，只生成缺失音频。`dev.ps1` 的部署步骤会复制该目录；下一次 Run 会加载名称清单。运行时将本地生成的距离与“进入”前缀、预生成名称、“城区，请注意减速慢行”后缀统一为 24 kHz 单声道 PCM 后拼接，并缓存完整句子。片段缺失或校验失败时使用普通城区提示，不将外语名称交给本地模型，也不自动发起云端请求。音频与清单属于本地产物，不提交源码仓库。
